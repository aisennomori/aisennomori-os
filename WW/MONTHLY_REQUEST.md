# ワカバウォーク 日別勤務表 ─ 毎月更新用・確定依頼文

> **使い方**
> 毎月、翌月分のPDFとあわせて以下をそのまま渡す。
> 実際には「○月分です。MONTHLY_UPDATE_RULES.md と毎月更新ルールに従って追加をお願いします。」＋PDF で足りる。
>
> **このファイルと `MONTHLY_UPDATE_RULES.md` の役割分担**
> - 本ファイル ＝ 毎月貼り付ける**依頼文**（何をやってほしいか）
> - `MONTHLY_UPDATE_RULES.md` ＝ **作業基準と過去月の記録**（どうやるか／前月までの実測値・座標・差分履歴）
>
> 両方に書かれている項目が食い違った場合は、**本ファイルを優先**する。

---

翌月分の人員計画表PDFです。

既存の `wakaba-shift.html` および `MONTHLY_UPDATE_RULES.md` に従って、翌月分を追加してください。

既存月データ・既存UI・既存ロジックは原則変更せず、今回の新しい月のデータ追加を主目的としてください。

---

## 最重要原則

- PDF原本を正本とする
- 推測禁止
- 判読不能は「要確認」
- 既存月データを削除・上書きしない
- 社員情報は月ごとに保持する
- **社員No.だけで同一人物と推測しない**
- 基本契約変更も月ごとに保持する
- 既存HTMLを全面作り直さない

---

## 勤務区分

| PDF表記 | status |
|---|---|
| ○ | `public_holiday`（公休） |
| ● | `requested_leave`（申請休） |
| 時刻記載 | `work` |
| 出張 | `business_trip` |
| 休職 | `leave_of_absence` |
| 判読不能 | `needs_review` |

**PDFに明記されていない区分を、周囲の状況から推測して付与しないこと。**

---

## 時刻

```
0630 → 06:30      残業  1.00 → 1時間00分
0700 → 07:00            1.30 → 1時間30分
1645 → 16:45            0.20 → 0時間20分
2200 → 22:00
```

小数時間として計算しないこと。

---

## PDF読取前の必須処理

まずスキャン品質を確認する。

- 回転
- 傾き
- 折れ
- 影
- 格子線
- ページごとの歪み

**傾きがある場合は、格子検出より先に傾き補正を行うこと。**
2026年8月分では、約0.4°の傾きでも格子検出が破綻した実績がある。

---

## 列構造チェック

日付データ抽出前に、**実日付列／週計列／日付ラベル列**を確実に分離する。

**最重要チェック：ヘッダーの日付が 1, 2, 3, 4 … と正しく連番になっていること。**

2026年8月分では、日付ラベル列の境界を誤認すると全セルが1列ずれる事象が確認されている。ヘッダー連番確認を通過してから社員セルの抽出へ進むこと。

---

## 毎月の処理順

| STEP | 内容 |
|---|---|
| 1 | PDF構造確認 |
| 2 | 傾き・回転補正 |
| 3 | 日付列・週計列・行ブロック検出 |
| 4 | 社員一覧抽出 |
| 5 | 前月との構造差分を確認 |
| 6 | 社員×日付の全セル抽出 |
| 7 | 勤務／公休／申請休／出張／休職を分類 |
| 8 | 開始・終了・残業を構造化 |
| 9 | 要確認一覧作成 |
| 10 | 月計・残業月計照合 |
| 11 | 午前／午後／夜の公式人員照合 |
| 12 | 検証結果報告 |
| 13 | 問題がなければ `SHIFT_DATA` へ翌月を追加 |
| 14 | `wakaba-shift.html` 更新 |
| 15 | 既存月への回帰がないことを確認 |

## 必須検証

対象月について集計する。

```
社員数 / 日数 / 総セル数
勤務セル数 / 公休数 / 申請休数 / 出張数 / 休職数 / 要確認数
```

さらにPDF記載値と照合する。

```
月計          全社員
残業月計      全社員
午前人員      8:00～10:00
午後人員      14:00～16:00
夜人員        19:00～21:00
```

不一致がある場合は、**①誤読 ②定義差 ③帳票構造差** を区別して原因を報告すること。

---

## 出張

PDFに「出張」と記載されている場合は、そのまま「出張」とする。

- 時刻記載がない場合は、**勤務バーを推測して描画しない**
- アプリ集計には含めない
- PDF公式人員に出張者が含まれている場合は「出張者を除くため差異あり」として定義差を明記する

---

## 初期表示

現在の仕様を維持すること。**このロジックは変更しない。**

1. 今日の日付が `SHIFT_DATA` に存在する → 今日を初期表示
2. 存在しない → 登録済み最新月の1日を表示

---

## 表示仕様

縦軸＝社員、横軸＝06:00～22:00。以下を既存仕様のまま維持する。

- 社員名 sticky
- 勤務バー／開始・終了時刻／残業表示
- 公休／申請休／出張／休職／要確認

**22:00位置には人数数字を表示しないこと。**
最終ビンは21:45～22:00の人数であり、22:00時点の人数と誤認されるため。

---

## 既存データ保護

現在、以下の確定データが存在する。

```
2026-08   33名 × 31日 = 1,023件   verified: true
2026-09   33名 × 30日 =   990件   verified: true
```

新しい月を追加しても、これらを変更しないこと。**社員No.や契約情報が翌月と違っても、過去月を上書きしない。**
