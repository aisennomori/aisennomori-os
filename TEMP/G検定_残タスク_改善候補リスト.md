# 残タスク・改善候補リスト

最終更新：2026年8月20日

**現時点で必須の作業はありません。** 以下はすべて「実運用で必要性が確認できたら着手する」候補です。

---

## A. 実運用で確かめること（機能追加より先）

### A-1. 瞬殺トレーニング26論点の妥当性

まず1セット回して、次の2点を見る。

- **10秒を超えた論点**はどれか → 最優先で反射化すべき箇所
- **5〜10秒の論点**はどれか → 反射化の途中。あと少し
- **26論点で足りているか／多すぎないか**

判断材料が揃ってから、論点の入れ替えや追加を検討する。

### A-2. 比較チップ10個の使用実績

用語集の比較チップについて、次の2つを拾う。

- **実際に使ったチップ**はどれか
- **手入力したが候補になかった比較**は何か

前者が少なければ枠を空け、後者が溜まればそこへ足す。

**チップ化の判定基準**（追加前に必ず検索して確認する）

| 検索結果 | 判断 |
|---|---|
| 上位2件に両方が出る | チップ化する価値あり |
| 片方しか出ない | 効果が薄い |
| 件数が多すぎて絞れない | 効果が薄い |

過去に「畳み込み vs プーリング」（12件）と「第三者提供 vs 委託」（1件・無関係）をこの基準で候補から外している。

### A-3. 検索の3段階の使用比率

「ローカルで即決／Webまで／AIまで」のどこまで進んだかを意識する。

| 到達点 | 意味 | 対応 |
|---|---|---|
| ローカルで即決 | 現状で足りている | 何もしない |
| Webまで | 教材に語はあるが決定打が弱い | `SEARCH_SYNONYMS` か補完語の候補 |
| AIまで | 教材の外の理解が必要だった | シラバス内なら `SYLLABUS_EXTRA` の候補 |

**「AIまで行った検索語がシラバス内だった」ケースが最も価値が高い。** 教材そのものの穴を示すため。過去に話者識別・スキップ結合をこのパターンで追加した。

## B. 学習面の優先課題

### B-1. 共通弱点 T12・T14・T15

第1・第2セットの両方で落としている領域。

| シラバス | 項目 | 第1 | 第2 |
|---|---|---|---|
| T12 | 活性化関数 | 誤答 | 誤答 |
| T14 | 正則化 | 誤答 | 誤答 |
| T15 | 誤差逆伝播法 | 誤答 | 誤答 |

問題を変えても再度落としているため偶発ではない。**瞬殺トレーニングのT02（勾配消失/爆発）・T04（L1/L2)・T19（活性化関数）がちょうどこの領域**にあたるので、まずここを定着させる。

### B-2. 誤答の型が変化している

第1セットは誤答12問が幅広い型に散っていたのに対し、第2セットの誤答7問は `comparison` 3・`application` 2 に集中している。

**用語を知らないのではなく、似た概念のどちらを選ぶかで落ちている。** 知識を足すより「違いを一文で言えるか」を確認する形が効く。

### B-3. 反射化できない領域

インプレス191問の分析では、**検索が有効な問題は2%、検索非推奨が40%**だった。

| 分類 | 割合 | 対応 |
|---|---|---|
| 所属・仲間外れ | 25% | 瞬殺トレーニングでカバー |
| 比較 | 31% | 同上 |
| **検索非推奨** | **40%** | **瞬殺では解決しない** |

「最も不適切なものを選べ」型は4つの記述すべてを検証する必要があり、反射化の対象外。**瞬殺トレーニングはM+C型（56%）専用の道具**であり、これだけでは合格に届かない。

第2セット誤答のうちP037（畳み込み出力サイズ）とP041（報酬設計）も、計算・判断型のため意図的にカード化していない。

## C. 実装候補（優先度順）

### C-1. SEARCH_SYNONYMS の拡充　優先度：中

現在5組。実運用で「一部の語しか一致しませんでした」が出た語を1組ずつ足す。

```js
const SEARCH_SYNONYMS = [
  ['画素', 'ピクセル'],
  ['個体', 'インスタンス'],
  ['誰', '話者'],
  ['見逃し', '偽陰性'],
  ['誤検知', '偽陽性'],
  // ここに追加
];
```

**注意**：片方向にしか成り立たない語を入れると無関係なカードが上位に紛れる。実際に検索して出なかった語だけを足すこと。追加後は既存の上位2件が変わっていないか検証する。

### C-2. 用語集への追加候補　優先度：中

インプレス分析で「430語に無い」と判定された語のうち、シラバス記載かつ未追加のもの。

| 分野 | 語 |
|---|---|
| 評価指標 | RMSE / MAE / MSE |
| 個人情報 | 要配慮個人情報 / 個人関連情報 / 共同利用 / 事業承継 |
| 画像 | SegNet / DeepLab / PSPNet / FPN / NASNet |
| NLP | ELMo / fastText / 位置エンコーディング / Multi-Head Attention |
| 転移学習 | Zero-shot / One-shot / 教師強制 |
| 強化学習 | 割引率 / Agent57 / Ape-X / AlphaStar / OpenAI Five / sim2real / 報酬成形 |
| 畳み込み | Depthwise / Pointwise / Dilated / Atrous Convolution |
| 数理 | 疑似相関 / 偏相関係数 / MDS |
| 歴史 | ダートマス会議 / MYCIN / SHRDLU / 東ロボくん / ワトソン |
| その他 | ノーフリーランチの定理 / オッカムの剃刀 / RandAugment / BPR / IaaS / PaaS |

**追加しないもの**：XGBoost / LightGBM / スタッキング / AdaDelta / Elastic Net / VQ-VAE / Pix2Pix（いずれもシラバス外）。437語の「ここだけは押さえる」性格を保つため。

### C-3. 選択肢シャッフル（100問アプリ）　優先度：中

既存100問は正解が①に64問偏っている（①64／②29／③6／④1）。繰り返し解くと位置で覚えてしまう。

実戦テストには既にシャッフルが入っているため、**既存100問側にも入れるかどうか**の判断。正解番号との整合を崩さない実装が必要。

### C-4. 弱点優先出題　優先度：低

誤答回数の多い問題を優先的に出す。現在は「間違えた問題」フィルターで代替できている。

### C-5. 模擬試験モード　優先度：低

本番と同じ145問・100分。ただし現在160問しかないため、問題数が足りない。

### C-6. 第3セット（実戦問題）　優先度：低

第1・第2セットを両方こなし、初見問題が尽きてから検討する。

### C-7. PWA / ダークモード　優先度：低

意図的に未実装。安定性を優先している。

### C-8. 瞬殺トレーニングの機能追加　優先度：低

いずれも使用実績を見てから判断する。

- 仲間外れだけ／比較だけのフィルター（現在は `cat` で代替可能）
- 10問モード（20問が3〜4分なら分割不要）
- 定着カードの一覧表示
- 5秒／10秒の閾値調整（実運用で緩すぎ・厳しすぎがあれば見直す）

## D. 保守上の注意点

### D-1. シラバス改訂時

`jdla_syllabus_v1_4.json` が55項目の正本。改訂があれば次を確認する。

1. 削除された語が3アプリに残っていないか
2. 新設された語が用語集に無いか
3. `SYLLABUS_EXTRA` の `syllabusId` が有効か

過去の第1.4版では「ChatGPT・GPT-n」の削除と「破壊的忘却→破滅的忘却」の表記変更があった。

### D-2. Google AIモードの `udm=50`

**非公式パラメータ。** Googleが変更・廃止する可能性がある。

`GOOGLE_AI_MODE_UDM` として1箇所に定数化してあるため、修正は1行で済む。無効化されても通常検索へフォールバックするだけで、リンクは壊れない。

### D-3. 3ファイルの配置

瞬殺トレーニングから用語集へのリンクが相対パス（`gkentei-yougo.html?q=...`）のため、**同じ階層に置くこと**。

### D-4. 変更時の手順

1. **バックアップを取る**（`backup/` へ日付入りで）
2. **差分を最小にする**
3. **回帰テストを流す**（合計824項目）
4. データ整合性を確認（CHAPTERS・STUDY_META・既存100問は無変更が原則）

### D-5. テストの保守

既存テストが落ちたとき、**仕様変更による意図した変化なのか、回帰なのかを必ず切り分ける。** 過去に「1語検索では章を表示する」「空欄時はボタンを隠す」など、仕様変更で旧テストが落ちたケースが複数ある。

## E. 参考：これまでに検出した不具合

同種の問題を再発させないための記録。

| 不具合 | 原因 | 教訓 |
|---|---|---|
| 選択肢タップだけで採点された | 仮選択と採点済みを同じ変数で判定 | 状態を明確に分ける |
| 個別回答時間が数秒しか記録されない | 再描画のたびに開始時刻をリセット | 再描画と画面遷移を区別する |
| 正解位置が②に18問偏った | 無意識の作問クセ | 機械監査を必ず通す |
| 正解位置が1,2,3,4の周期になった | 均等配分の副作用 | 周期性も検査項目に入れる |
| ボタンのラベルが白抜けした | 存在しないCSS変数を使用 | 実ファイルの変数名を確認する |
| A4シートが5ページに溢れた | 印刷CSSの余白過多 | PDF化して実測する |
| シートにT08の掲載漏れ | 手作業のID列挙 | 自己検査を組み込む |
| スマホで検索欄が179pxに潰れた | `width:50%` 固定 | 実機幅で必ず測る |
